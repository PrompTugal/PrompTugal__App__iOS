CI status: from push to production

A push to dev goes two ways. The website workflow tags a release and deploys this site; it is live when the deploy job reads the new release back from the live version.json. The iOS workflow builds and tests on a Mac, then signs the apps from the release commit and uploads them to TestFlight; App Store Connect then processes each build before testers can install it. “Push to live” below is the time from the push to each of those moments.

This page is the copy from the last site build. The live copy, rewritten about every ten minutes by ci-status.yml, is ci-status.json on the ci-status branch; the app’s Status screen (More, then CI status) reads it and says how long ago it was checked, and whether the build on the device has a newer one in TestFlight. This build’s copy is ci-status.json.
