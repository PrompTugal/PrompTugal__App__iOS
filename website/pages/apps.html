Why three

A public app should hold only public things

  • The public app has no team data. No team names, no messages between people, no debug panels. Anyone can install it and use it without keys.
  • The team keeps its tools. The Team app has every tool the team had in the one app, and it never needs App Review.
  • Shared code, built once. The apps share local Swift packages. A change to one app’s code builds and uploads only that app. A change in a shared package builds every app that uses it.

The plan and the rules are in the three-apps brief. The privacy page of this app is here; the Team app has its own.
