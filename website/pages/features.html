How we decide where a feature lives

We ask four questions, in order, and the first “yes” decides.

  1. Does it need the device? Face ID, the Keychain, notifications, widgets, the camera, background refresh. Then it is native.
  2. Does it hold a secret or private data that must survive? Then the key is native and the data goes in the vault.
  3. Is it content, or a workflow that changes every week? Articles, agenda pages, search. Then it is web, shown inside the app.
  4. Do people do it while walking between halls? Checking what is next, saving a session. Then it is a native fast path over the website’s data.

Some features are built both ways on purpose, side by side, so we can see which works better on a phone and on an iPad.
